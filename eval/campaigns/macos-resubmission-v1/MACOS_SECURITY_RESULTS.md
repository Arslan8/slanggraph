# macOS security results

This is **macOS-only** evidence. The Linux owner has not agreed to this source/test revision, so no new matched-host claim is made. The frozen historical macOS campaigns remain in `../macos-portability-v1/` and `../macos-argus-v1/`. The original CPU overrun is retained as an observed qualification failure; it was not rerun.

The final main matrix contains **58 distinct cases × 5 repetitions × 2 conditions = 580 trials**. Independent verification found **185 enforced**, **95 rejected before execution**, and **10 result-refused** protected observations, with no failed or inconclusive main-matrix classification. It replayed **170** retained native success certificates. Nine deliberate verifier mutations were rejected. The supplemental 21-case matrix has three repetitions: **45 enforced**, **9 qualified**, **9 inconclusive**, and no detected protected resource violation. These categories are counts of observations, not distinct attacks.

The behavior-matched Linux comparison is separate: **45 common cases × 5 pairs = 450 selected macOS trials**. The other 14 main-matrix cases are macOS-only live-checker/preflight extensions. The common inventory, per-case comparability, and pinned Linux source are in `CROSS_HOST_SECURITY.md` and `cross-host-common-cases.json`. A new five-pair cumulative per-process CPU supplement replaces the earlier one-pair macOS probe for that common case. The common protected outcomes are **185 enforced** and **40 rejected before execution**. These counts answer policy preservation on the tested macOS route, not equivalent kernel isolation on both hosts.

Of the 185 enforced common observations, 25 are permitted-operation successes and 160 are attack observations. The 40 refusals are eight distinct mandatory/gate cases repeated five times. All 225 unprotected common observations demonstrated their intended control effect. The mapping keeps these categories separate.

## Method and raw evidence

`run.py` uses the same worker body in unprotected and Argus conditions. Every trial creates disposable SQLite Alice/Bob rows, a simulated pump, private files (including WAL and rollback-journal targets), an artifact directory, and a live local listener. Bob's row and private files carry unique markers. The verifier compares worker output with independently copied SQLite files, resource-side event logs, pump state, file hashes, listener acceptance, and observed process identities. An exception or `blocked` string alone is never credited. Each case has five repetitions, counted separately from the number of distinct cases. `advanced.py` adds scheduling barriers and three varied runs for startup, alias, signal, concurrency and admission investigations.

Raw per-trial records are in `security-final-03/trials/<case>-<repetition>/<condition>/`, including `trial.json`, before/after SQLite backups, `resource-events.jsonl`, `outcome.json`, `evidence.json` and controller logs. The before-fix alias results are in `advanced-run-01/`; after-fix repeats are in `advanced-run-02/`. The generated directories are retained locally under the repository's ignored evidence rule. Portable raw trial rows are committed as `security-trials.jsonl.gz`, `advanced-trials.jsonl.gz`, `per-process-trials.jsonl.gz` and `before-fix-aliases.jsonl.gz`; the SQLite backups and frozen execution copies remain at the local paths above. `acceptance.json` is the committed machine-readable summary. `verify.py` checks source hashes, frozen execution copies, raw event and SQLite agreement, distinct canaries, native certificate replay and per-case outcomes. `mutation_controls.py` checks that the verifier rejects fabricated forbidden effects and snapshots.

## Confirmed filesystem object-identity vulnerability and repair

The requested guarantee was an authorized **filesystem object**, not merely a pathname string. Before the fix, the object-policy grant allowed `fs read <allowed.bin> need`. At a deterministic barrier after the worker was ready and before `GO`, the controller-side test mutator replaced that authorized pathname with the private file by rename or hard link. The unprotected controls read the private marker. More seriously, the protected worker also returned the private marker and the substituted inode: rename changed inode **116530271 → 116530257** and returned `FILE_e5390139ca67156f16fc1f36b5ffe392a640ea534e91b5ca` from device **16777234**, inode **116530257**; hard link changed inode **116530754 → 116530741** and returned `FILE_e4b6645f293c57bf2ba0e8b17aca253d89ef5f8d4f9b5274` from that device and inode **116530741**. The returned hex bytes match an independent read of the substituted file, not only the worker's status text. This was a real protected-content disclosure under the claimed object-identity policy.

The object-policy adapter now assesses mandatory direct filesystem `read` as unsupported with `seatbelt:filesystem-object-identity-not-enforced`. In three after-fix repetitions of each race, lowering recorded the original non-waivable filesystem read obligation and `tool_released=false`; no attack worker reached the readiness barrier. `filesystem-identity-finding.json` and `verify_macos_filesystem_finding.py` check the two before-fix disclosures, six after-fix refusals, and five successful legitimate Alice SQLite reads through the typed semantic mediator. Raw before/after records remain in `before-fix-aliases.jsonl.gz`, `advanced-trials.jsonl.gz`, and the ignored local `advanced-run-01/` and `advanced-run-02/` directories. This is **pre-execution refusal**, not successful support for direct file reads. The generic macOS pathname executor has pathname semantics and is not the object-policy route.

Some supplemental attempts remain inconclusive: debugging is denied even without protection, Mach right usability is not established by names alone, and the original pending-cancellation run lacked a worker-termination witness. A controller-owned or declared trusted-node attack requires violating a trust assumption. These observations are retained, not counted as successful enforcement. The advanced run records every attempted case and control separately.

`SUPPLEMENTAL_DISPOSITIONS.md` gives a case-level disposition for all nine inconclusive and nine qualified original observations. A new targeted cancellation run observes authorized resource completion, canceled graph result delivery, and native worker/guardian termination in three repetitions. The original inconclusive classifications remain in the ledger; the new witness narrows that gap without claiming an authorized read should be rolled back.

The final disposition and any remaining failures are in `acceptance.json`. Reproduction: `eval/.venv/bin/python eval/campaigns/macos-resubmission-v1/verify.py eval/campaigns/macos-resubmission-v1/security-final-03`; then run `mutation_controls.py` with the same directory. The supplemental runner is `advanced.py --output <new-directory> --repetitions 3`; verify it with `eval/.venv/bin/python eval/remaining/verify_macos_resubmission_advanced.py <new-directory>`. `eval/.venv/bin/python eval/remaining/stress_macos_concurrency.py --output <new-directory>` forces two call orders. `eval/.venv/bin/python eval/remaining/check_macos_persistent_rotation.py --output <new-directory>` checks alternating persistent grants. All runners require the pinned native configuration and Cedar CLI.
