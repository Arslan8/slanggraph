# macOS proof-to-execution map

| Claim or mutation | Production receiver and gate | Observed consequence | Remaining premise |
| --- | --- | --- | --- |
| Generated resource obligations cover the grant | `_MacOSObjectWorker._prepare_execution` calls `_check_lean_grant`, then `LeanLifecycleChecker.require_grant` | Missing obligation and altered selector live mutations refuse before worker release; independent trace has no `entered` event | Grant compiler and obligation serialization correspond to the actual resources |
| Principal, session, tool, invocation and artifact are bound | `MacOSObjectDispatcher._invoke`, `_MacOSObjectWorker._compile_grant`, `_ObjectBroker._handle_frame`, and `LeanLifecycleChecker._require` | Binding mutations and broker frame substitutions are refused; SQLite/event snapshots show no Bob effect | Trusted authentication adapter binds the real caller to `Principal` |
| Plan activation precedes GO | `MacOSSandboxExecutor._invoke` and `LeanLifecycleChecker._require` | Altered activation evidence is refused before execution | Native launcher and guardian implement reported state |
| Result release follows confirmed termination | `MacOSSandboxExecutor._invoke` and `LeanLifecycleChecker._require` | False or unconfirmed cleanup evidence withholds the result even where the tool body already ran; post-cleanup resource observations are separate | Controller, guardian and OS process identity observations are accurate |
| Cedar and sealed operator policy are used | `ObjectPolicyHostExecutor`, `RuntimeMAC`, closed admission, and `evaluation.assert_complete_path` | Missing-component preflights fail; one allowed Alice read succeeds and Bob read is denied | Cedar CLI and trusted controller configuration |
| Direct resource bypass is closed | `_MacOSObjectAdapter.assess`, Seatbelt launcher, and typed mediator | Direct SQLite and private-file controls access data without protection; protected worker cannot, while semantic Alice read succeeds | Seatbelt path/IPC enforcement and mediator implementation |

The compiled Lean core checks the model predicates over encoded grants, obligations, activation events and cleanup certificate. `ResourceGrantCoverage.lean` proves exact generated resource-obligation inventory and service guards; `ReceiptCoverage.lean` checks assignment/evidence coverage and binding; `WorkerRoute.lean` proves that `GO` follows matching activation and success follows confirmed cleanup. These properties do not prove macOS kernel behavior, Cedar policy correctness, Python controller integrity, arbitrary application node confinement, or the accuracy of the controller's observations. Live mutation cases in `security-final-03` exercise the actual call path. Certificate replay in `verify.py` checks retained traces separately and cannot establish that an unrecorded call passed the live gate. See each trial's `evidence.json` and `resource-events.jsonl` for the receiving phase and independent resource observation.
