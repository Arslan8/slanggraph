## Failure analysis

The Pandas pre-fix v22 matched run is retained: baseline 10/10, protected 9/10,
with `monthly_mean` rejected by `output_data:nonfinite_float`. The first repair
made the helper produce Python `None`, but the vendor reconstructed a numeric
DataFrame and converted it back to `NaN`; that unsuccessful attempt is also
retained. v23 uses a versioned sentinel only for the missing numeric bucket,
allows the unchanged strict validator to inspect a finite/string state, and
restores JSON `null` only at the admitted wrangling boundary. The final matched
run at `0db4bf9f3f7cbf13fecb5c1329dfd4decc1acf78` is 50/50 in both modes with
the original oracle. Baseline mean wall time is 10,228.4 ms and Argus mean is
11,388.9 ms: 1.113x, or 11.3% overhead, with a paired-block 95% interval of
10.7%-12.1%. See `pandas-final-0db4bf9f3-results/` for per-task results,
statistics, checksums, and independent validation.

T10 is not repaired by disabling checkpoint integrity. Restoring the selected
historical checkpoint is not a valid continuation of the authenticated current
chain. Supporting it requires an explicit authenticated branch/continuation
transition. D4's protected timeout is retained as a compatibility failure; no
model, task, or timeout change was made to hide it.

Compact fresh ordinary-app records are committed under
`retained/applications/`; Pandas before/intermediate/after records and their
configuration evidence are under `retained/pandas/`. Expanded local records
remain in the corresponding `raw/` campaign directories.
