This report diagnoses the retained `final-r2` records. It does not relabel, delete, or
reuse a failed trial as a success. Model-answer errors remain answer errors. The fixes
below require a new build and invalidate only the cells listed in the rerun plan.

## Independent Pandas oracle calculation

The frozen rows sum to January `100 + 60 + 100 = 260`, February `80 + 40 = 120`,
March `20 + 100 = 120`, and April `0` because its only sales value is missing.
The corresponding means are January `260 / 3 = 86.666666...`, February `60`,
March `60`, and April null. Filtering February before summing yields `120`.
These values were calculated directly from the CSV rows, not from generated model output.

## Qualification and rerun rule

The qualification gate records execution success separately from answer correctness. Every
macro task is run once in baseline, Argus, nono, and APF; all ten Pandas tasks are run once
in baseline and Argus; micro allowed/forbidden probes cover all three modes; Linux host
security retains its positive controls and effect oracles. Wrong answers do not fail the
integration gate, but unexplained execution, dependency, route, timer, or compatibility
failures do.

Rerun every D3, D4, D5, and T10 task in all macro conditions whose common source changed. Rerun
all APF macro cells because the APF timer changed. Rerun all Pandas cells because the shared
workflow contract changed. Rerun forced-host micro cells (including sustained host points)
because the native adapter and write grant changed; baseline/language micro cells retain explicit
compatible lineage. Rerun all Linux host-security cases because the shared Linux lowering changed.
Never combine an affected `final-r2` cell with the corrected build.
